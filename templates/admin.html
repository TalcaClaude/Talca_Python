Administración — Usuarios y roles

← Módulos Cerrar sesión {% include "_notificaciones.html" %}

Cada usuario tiene un rol que determina qué puede hacer, además de lo que ve en pantalla: admin puede todo (incluyendo este panel); finanzas registra facturas de compra y administra Caja Chica / Cuentas por Cobrar y Pagar; bodega aprueba o rechaza la recepción de mercadería (contra lo que llegó físicamente) y administra el inventario; operativo trabaja las órdenes de trabajo del taller; convertidores trabaja el módulo de Convertidores de Torque. El bloqueo por rol se aplica también del lado del servidor, no solo ocultando botones.

Usa las mismas credenciales del respaldo automático. Una vez al día revisa si hay productos en o bajo su stock mínimo, y si hay alguno, avisa por correo — si no hay ninguno, no manda nada.

Cargando…

Respaldos automáticos locales (cada 1 hora)

El sistema guarda copias automáticas de la base de datos cada 1 hora en el mismo servidor, además del respaldo diario por correo. Sirven para volver a "hace poco" ante un error, sin depender de que llegue el correo del día. Si el disco queda con menos de 100 MB libres, se salta el respaldo automático en vez de arriesgarse a llenarlo.

Mantenimiento

Limpiar cuentas por cobrar que quedaron pegadas de una OT que ya no está en "listo" ni "entregado" (bug ya corregido para casos nuevos — este botón limpia lo que haya quedado de antes). No toca ninguna CxC que ya tenga un pago registrado.

Vaciar Caja Chica (solo pruebas)

Borra TODOS los retiros, boletas, aportes y rendiciones de Caja Chica para dejarla en $0 — pensado para probar el módulo sin que estorben datos de prueba, no para uso normal. Si alguno de esos gastos había ingresado stock al inventario (compra de emergencia), esa entrada de stock NO se revierte sola; el botón te avisa si encuentra algún caso así para que revises el inventario a mano. Descarga un respaldo antes si quieres poder volver atrás.

Reseteo de datos operativos (para migración desde PHP)

Deja en blanco todo lo operativo — órdenes de trabajo, productos de bodega, convertidores de torque, garantías, facturas de compra, cuentas por pagar/cobrar, caja chica, documentos tributarios y todo lo que se genera a partir de eso — para poder cargar encima la base migrada desde el sistema PHP antiguo. Clientes, sus vehículos (equipos), usuarios del sistema y los catálogos (categorías/marcas/modelos/ubicaciones) NO se tocan. Crea un respaldo automático antes de borrar cualquier cosa; aun así, te recomendamos descargar también un respaldo manual (sección de arriba) antes de continuar.

Migración: repuestos/mano de obra de garantías

    
Carga el archivo garantias_items_extraidos.json (extraído del sistema anterior) para agregar los repuestos y mano de obra históricos a las garantías que ya están migradas. Solo agrega ítems informativos — no toca stock ni el catálogo. Es seguro correrla más de una vez: las garantías que ya tengan estos ítems se saltan.
